# AUROC 如何检测幻觉？——以 CLARIFY 实验为例

> 本文用**手算级别的例子**解释：幻觉检测的标签怎么来、分数怎么构造、AUROC 到底是什么、项目实测数字怎么解读。
> 对应的真实代码：`experiments/phase7_three_directions/C2_truth_direction.py`、`experiments/lin_theory/detect_lr_probe_cv.py`、`detect_js_lr_cv.py`。

---

## 0. 一句话总结

**幻觉检测 = 给每个样本打一个"可疑度分数"，再验证"幻觉样本的分数是否稳定地比正确样本更可疑"。AUROC 就是这把"验证尺子"：它等于随机抽一个幻觉样本、一个正确样本，幻觉样本分数更可疑的概率。**

完整流水线：

```
TriviaQA 样本
   │  ① 模型 greedy 生成答案
   ▼
生成文本 ──② exact 匹配参考答案──▶ 标签（正确 / 幻觉）
   │
   │  ② 知识筛选（可选，见 §2）：剔除"无知"样本，只留"模型知道"的子集
   ▼
高知识子集
   │  ③ 提取内部状态 / 输出分布
   ▼
特征 h ──④ 构造分数（truth direction 投影 / LR probe / max_p）──▶ 每个样本一个分数
   │
   ▼
⑤ 5 折 CV：训练集拟合"打分器"，测试集打分 → 排序 → 算 AUROC
   │
   ▼
⑥ 验证集上定阈值 θ：分数 < θ → 判定"疑似幻觉"
```

下面每一步都用实际例子展开。

---

## 1. 第一步：定义"幻觉"（判定依据的核心）

项目用的是**生成正确性**定义：让模型自己回答，答错了就是幻觉样本，答对了就是非幻觉样本。

**真实样本**（TriviaQA `rc` 子集，validation split，项目实际使用的数据）：

| # | 问题（真实） | 参考答案 aliases（真实） |
|---|---|---|
| S0 | What name is given to the hot, molten rock found under the surface of the earth? | `MAGMA`, `Magma (disambiguation)` |
| S1 | With 47 attacks in the year 2010 alone, what body of water is known as Pirate Alley? | `Gulf of Aden`, `Aden, Gulf of`, … |
| S2 | When sending an email you are given the option to 'Add Cc' or 'Add Bcc'. For which word is the 'B' the initial letter? | `Blind carbon copy`, `Undisclosed recipients`, … |

模型拿到的 prompt 结构（`format_prompt`，问题在末尾）：

```
Based on the provided context, answer the question with a single word or short phrase.

Context: （6 段左右搜索引擎检索到的上下文，最长可达 9 万字符）
...
Question: What name is given to the hot, molten rock found under the surface of the earth?

Answer:
```

**打标签**（`check_correct_exact`，词边界精确匹配）：

| 模型生成（示意） | 判定 | 原因 |
|---|---|---|
| `magma` | ✅ 正确 | 与别名 `MAGMA` 词边界匹配 |
| `magma is hot molten rock` | ✅ 正确 | 含 `magma` 完整词 |
| `lava` | ❌ 幻觉 | 与任何别名都不匹配 |
| `the magma` | ✅ 正确 | 词边界匹配不要求全句相等 |

⚠️ 这个标签定义是**判定依据的第一层**：一切 AUROC 都建立在"答错 = 幻觉"上。项目吃过亏：早期用 fuzzy 匹配（词集有交集就算对），有 **28% 假阳性**——上下文中往往含答案词，模型照抄上下文也被判"对"，标签被污染。

## 2. 第 1.5 步：知识筛选——先剔除"无知"，再谈"幻觉"

### 2.1 为什么要先筛选

项目在第 1 步发现过一个根本问题（`main_knowledge_filtered.py` 文件头）：

> 检测失效是因为准确率太低（52%）——大多数"错误"是**随机噪声（无知）**，不是真正的幻觉。如果先按 P(correct) 筛出"高知识"样本，正确/错误的内部状态差异会清晰得多。

直观理解：**"不知道答案瞎蒙"和"知道答案却编造"在内部状态里是两种东西**。把"无知"样本混进标签里，等于让检测器同时学两套模式，互相干扰。

### 2.2 实现：4-way softmax 给"正确选项"打分（HellaSwag 版）

HellaSwag 是多选题（A/B/C/D 四选一），模型在最后一个 token 给四个选项字母各一个 logit：

```python
letter_ids = [tokenizer.encode(l)[0] for l in "ABCD"]  # 4 个字母的 token id
letter_logits = logits_final[letter_ids]                # 取出 4 个 logit
probs = softmax(letter_logits)                          # 4-way softmax
p_correct = probs[正确选项的字母]                        # 模型认为"知道"的程度
```

**手算例子**（示意 logits）：

| 选项 | logit | softmax 概率 |
|---|---|---|
| A（正确） | 2.0 | **0.70** |
| B | 0.5 | 0.14 |
| C | 0.3 | 0.12 |
| D | 0.0 | 0.04 |

p_correct = 0.70 > 0.3 → **保留**（模型很确定选 A）

另一个样本（模型瞎猜）：

| 选项 | logit | softmax 概率 |
|---|---|---|
| A（正确） | 0.1 | **0.28** |
| B | 0.2 | 0.31 |
| C | −0.1 | 0.23 |
| D | −0.3 | 0.19 |

p_correct = 0.28 ≤ 0.3 → **剔除**（模型根本不知道，谈不上幻觉）

### 2.3 效果：检测能力大幅提升

| 检测方法 | 全量样本（不筛选） | 知识筛选后（p_correct > 0.3） |
|---|---|---|
| max_p @L28（HellaSwag） | AUROC **0.68** | AUROC **0.87** |

同样一个信号，筛选后 AUROC 提升 0.19——**"无知"样本确实在拖累检测**。这是"幻觉≠无知"最直接的实验证据。

### 2.4 TriviaQA 上的对应物：knowability rank 分类

TriviaQA 是开放问答（没有 ABCD 选项），没法做 4-way softmax。项目的替代方案是 **knowability 分类**（TLDC 用）：

> 正确答案第一个 token 在模型 logits 里的 **rank ≤ 50** → 模型"知道" → 样本进入 KW（知道但答错）/ KC（知道且答对）；rank > 50 → "不知道" → DK 子集。

这就是为什么 TLDC 实验里有 KW/KC/DK 三组：**DK（dont't know）就是被"知识筛选"剔除的样本**——干预只应该针对 KW（模型知道却答错），而不是 DK（干预一个不知道答案的模型没有意义）。

⚠️ 注意：知识筛选同样有任务依赖性问题——HellaSwag 的 4-way softmax 不能直接搬到 TriviaQA，需要换成 rank 判据；而 rank 判据本身又被 TLDC 的 D2 实验质疑过（见 code-review 重审节）。

## 3. 第二步：构造"幻觉分数"（信号）

标签是"对/错"两类，AUROC 需要的是**连续分数**。项目用了三种信号：

### 2.1 truth direction（`C2_truth_direction.py`）——内部状态投影

**思想**：幻觉样本和正确样本在模型的内部状态（残差流）里位于不同区域。先学一个方向 v，把每个样本的状态投影上去，投影值就是分数。

**手算例子**（把 2048 维简化成 2 维）：
训练集 4 个样本的 last-token 激活：

| 样本 | 激活 h | 标签 |
|---|---|---|
| 1 | (1, 2) | 正确 |
| 2 | (2, 1) | 正确 |
| 3 | (0, 0) | 幻觉 |
| 4 | (1, −1) | 幻觉 |

```
v = mean(h_正确) − mean(h_幻觉)
  = (1.5, 1.5) − (0.5, −0.5)
  = (1, 2)，归一化后 v ≈ (0.45, 0.89)
```

对测试样本打分 `score = h · v`：

| 测试样本 h | 分数 | 解读 |
|---|---|---|
| (1.4, 0.2) | 1.4×0.45 + 0.2×0.89 ≈ **0.81** | 分数高 → 更像正确 |
| (−0.3, 0.1) | −0.3×0.45 + 0.1×0.89 ≈ **−0.05** | 分数低 → 更像幻觉 |

分数越高 = 越"像正确"，越低 = 越可疑。

### 2.2 LR probe（`detect_lr_probe_cv.py`）——每层一个逻辑回归

比均值差更强：在每层 hidden state 上训练 `StandardScaler + LogisticRegression`，输出 P(正确) 作为分数。**同样的思想，更强的分类器**——拟合时不只用均值，而是学整个线性边界。

### 2.3 表面特征（`detect_js_lr_cv.py`）——输出分布统计量

不看内部状态，只看输出：max_p（最高概率）、entropy（分布熵）、top-5、JS 散度（logit lens 早期层分布 vs 最终分布的距离）。思想：**幻觉 = 模型"自信地"或"不稳定地"输出**。

⚠️ 反直觉教训：项目实测 max_p 在 TriviaQA 上 AUROC 只有 **0.56**（接近瞎猜）——因为模型对错误答案常常**同样自信**。表面特征在开放问答上不可靠（后面第 6 节有完整数字）。

## 4. 第三步：AUROC 到底是什么（手算全过程）

### 3.1 6 个样本的例子

假设 6 个测试样本，分数已经算好（越高越像正确）：

| 样本 | 真相 | truth direction 分数 |
|---|---|---|
| A | 幻觉 | 0.7 |
| B | 幻觉 | 0.4 |
| C | 幻觉 | 0.3 |
| D | 正确 | 0.9 |
| E | 正确 | 0.6 |
| F | 正确 | 0.5 |

按分数从高到低排序：**D(0.9) → A(0.7) → E(0.6) → F(0.5) → B(0.4) → C(0.3)**

注意 A：它是个"自信的幻觉"（分数 0.7 排第三），一会儿看它如何拉低 AUROC。

### 3.2 画 ROC 曲线

把阈值 θ 从最高往最低扫：分数 ≥ θ 判"正确"，否则判"幻觉"。每扫一步记两个数：

- **TPR（召回率）** = 被正确判对的正确样本 / 正确样本总数（3 个里几个）
- **FPR（误报率）** = 被误判成正确的幻觉样本 / 幻觉样本总数（3 个里几个）

| θ | 判为"正确"的 | TPR | FPR | ROC 点 (FPR, TPR) |
|---|---|---|---|---|
| 0.95 | （无） | 0/3 = 0 | 0/3 = 0 | (0, 0) |
| 0.80 | D | 1/3 = 0.33 | 0/3 = 0 | (0, 0.33) |
| 0.65 | D, A | 1/3 = 0.33 | 1/3 = 0.33 | (0.33, 0.33) |
| 0.55 | D, A, E | 2/3 = 0.67 | 1/3 = 0.33 | (0.33, 0.67) |
| 0.45 | D, A, E, F | 3/3 = 1.0 | 1/3 = 0.33 | (0.33, 1.0) |
| 0.35 | D, A, E, F, B | 3/3 = 1.0 | 2/3 = 0.67 | (0.67, 1.0) |
| 0.25 | 全部 | 3/3 = 1.0 | 3/3 = 1.0 | (1, 1) |

把这些点连起来（横轴 FPR，纵轴 TPR），**曲线下方的面积就是 AUROC**：

```
TPR
1.0 ┤            ●──────●──────●     ← (0.33,1) (0.67,1) (1,1)
0.67┤        ●                        ← (0.33, 0.67)
0.33┤     ●──●                        ← (0,0.33) (0.33,0.33)
    └────────────────────────── FPR
     0    0.33    0.67     1
```

面积（梯形法，按相邻 ROC 点逐段算）：

| 线段（相邻 ROC 点） | ΔFPR | 平均 TPR | 面积贡献 |
|---|---|---|---|
| (0, 0) → (0, 0.33) | 0（竖线） | — | 0 |
| (0, 0.33) → (0.33, 0.33) | 0.33 | 0.33 | 0.111 |
| (0.33, 0.33) → (0.33, 0.67) | 0（竖线） | — | 0 |
| (0.33, 0.67) → (0.33, 1.0) | 0（竖线） | — | 0 |
| (0.33, 1.0) → (0.67, 1.0) | 0.33 | 1.0 | 0.333 |
| (0.67, 1.0) → (1.0, 1.0) | 0.33 | 1.0 | 0.333 |
| **合计** | | | **0.777 ≈ 0.78** |

### 3.3 AUROC 的另一种理解（更有直觉）

> **AUROC = 随机抽一个正确样本 + 一个幻觉样本，正确样本分数更高的概率。**

验证上面的例子：正确 {D=0.9, E=0.6, F=0.5}，幻觉 {A=0.7, B=0.4, C=0.3}，一共 3×3 = 9 对：

| | A(0.7) | B(0.4) | C(0.3) |
|---|---|---|---|
| D(0.9) | ✓ | ✓ | ✓ |
| E(0.6) | ✗ | ✓ | ✓ |
| F(0.5) | ✗ | ✓ | ✓ |

7/9 ≈ **0.78** —— 和曲线面积完全一致 ✅

**0.78 意味着什么**：78% 的情况下，检测器能把"对的"排在"错的"前面。那个"自信的幻觉"A（0.7 分）只破坏了 2 对——它一个人就把 AUROC 从 1.0 拉到了 0.78。这就是为什么 AUROC 是排序指标：**一个伪装得很好的幻觉样本，代价是每对组合扣一分。**

### 3.4 刻度参考

| AUROC | 含义 | 项目参照 |
|---|---|---|
| 0.5 | 排序等于抛硬币 | 表面特征在 TriviaQA 上 ≈0.56-0.63 |
| 0.7-0.8 | 中等：大部分能分开，但有不少误判 | truth direction 0.7564 / LR probe 0.7708 |
| 0.85+ | 良好：项目最初设定的达标线 | HellaSwag D2+max_p 0.936（但跨任务失效） |
| 1.0 | 完美排序 | 现实不存在 |

## 5. 第四步：为什么必须用 5 折交叉验证

分数不是凭空来的——v 或 LR 是**在样本上拟合出来的**。如果拟合和打分用同一批样本（in-sample），就是"考试时偷看答案"：

> 项目教训：旧代码在全部样本上拟合 v 又在同一批上打分，得到 **0.9066**；改用 5 折 CV 后同一信号只有 **0.7564**——虚高了 **0.15**。2048 维激活空间 + 100 个样本，线性方向严重过拟合。

5 折 CV 的做法（`C2_truth_direction.py:215-229`）：

```
100 个样本
 ┌─────┬─────┬─────┬─────┬─────┐
 │折1  │折2  │折3  │折4  │折5  │   5 等份，类别比例保持一致
 └─────┴─────┴─────┴─────┴─────┘
第 1 轮：折 2-5 拟合 v ──▶ 折 1 打分，算 AUROC
第 2 轮：折 1,3,4,5 拟合 v ──▶ 折 2 打分，算 AUROC
...共 5 轮
最终 AUROC = 5 轮均值 ± 标准差
```

每个样本的分数都来自"没见过它的"拟合，报告 `0.7564 ± 0.0549` 才是诚实的泛化能力。

## 6. 第五步：AUROC 定完信号后，怎么实际"判定"？

AUROC 只回答"排序好不好"，不回答"多高算幻觉"。实际检测还要**定阈值**：

```
验证集上：
  θ = 0.45 → 分数 < 0.45 的判"疑似幻觉"
  这时查：误伤了多少正确样本（FPR）？漏了多少幻觉（FNR）？
按业务需求选 θ：宁可多拦（低 θ）还是宁可少拦（高 θ）
```

项目目前停留在"AUROC 评估"层面（检测闭环达标线 = AUROC ≥ 0.85），但**阈值化的思想已经用在干预里**：TLDC 的 knowability 分类就是"正确答案在模型 logits 中的 rank ≤ 50 = 模型知道"——一个 rank 阈值，把样本切成"知道/不知道"，再决定要不要干预。

## 7. 项目实测数字与解读（判定依据的实证）

| 信号 | AUROC（修复后，5 折 CV） | 解读 |
|---|---|---|
| truth direction @L18 | **0.7564** ± 0.055 | 内部状态存在可学习的正确性方向 |
| LR probe @L26 | **0.7708** ± 0.056 | TriviaQA 线性检测的天花板 ≈0.77 |
| 表面特征（max_p/entropy/JS） | 0.56-0.63（joint 0.607） | 输出分布统计量在开放问答上无判别力 |
| 知识筛选后 max_p（**HellaSwag**） | **0.87**（筛选前 0.68） | 剔除"无知"样本后检测能力 +0.19 |
| **TriviaQA rank 筛选后 LR probe** | **0.7664**（rank≤50）≈ 全样本 0.7708 | **筛选无增益** → 0.77 是任务天花板（2026-08-25 验证） |
| D2 JS+max_p（**HellaSwag**） | **0.936** | 多选题任务达标 ✅ |
| 跨任务迁移 | 0.54 / 0.66 | 换任务后检测器失效 ❌ |

**四个结论**：

1. **幻觉在内部状态里"可探测但不可完美分离"**：0.75+ 说明 v/probe 学到的方向是真的，不是噪声；到不了 0.85 是因为 TriviaQA 上大部分"幻觉"其实是**无知**（模型准确率只有 39%，61% 的错误里很多是"根本不知道"，内部状态与"知道但答错"分不开）。
2. **知识筛选的效果是任务依赖的**：HellaSwag 上剔除"无知"后 max_p 0.68→0.87（+0.19）；但 **TriviaQA 上 rank 筛选（rank≤50）后 LR probe 0.7664 ≈ 全样本 0.7708，无增益**。机制解释：HellaSwag 的检测信号是输出面置信度（max_p），会被"无知的低置信"污染；TriviaQA 的信号是内部状态线性方向，本身已隐含知识信息——筛选掉的样本和检测器认为可疑的是同一批，排序结构不变。
3. **检测是任务依赖的（项目叙事重构）**：HellaSwag 0.936 换到 TriviaQA 只有 0.77，跨任务 0.54/0.66——多选题（干扰项竞争）与开放问答（知识检索）的幻觉机制不同，检测器与筛选器都不迁移。
4. **检测 ≠ 干预**：v 能 readout（检测 0.75+）但不能 control（10+ 干预范式全零效应）——"看得见"和"改得动"是两回事。

## 8. 常见误区（项目用真金白银踩出来的）

| 误区 | 项目教训 |
|---|---|
| in-sample 评估 | 0.9066 → CV 后 0.7564，虚高 0.15 |
| fuzzy 标签 | 28% 假阳性（照抄上下文判对），必须 exact 词边界 |
| AUROC 高 ≠ 分数可校准 | 0.936 的 HellaSwag 信号换任务就失效，排序好不代表哪都能用 |
| "幻觉"≠"无知" | 准确率 39% 时大部分错误是不知道——**解法 = 知识筛选**（HellaSwag 4-way softmax P(correct)>0.3，max_p 0.68→0.87；TriviaQA 用 rank≤50 替代） |
| 检测信号 ≠ 干预信号 | Phase 11-16：全部基于 v 的干预零效应，v 是 readout 方向 |

---

## 9. 判定依据三层总结

1. **标签层**：幻觉 = 模型生成与参考答案词边界 exact 不匹配（答错即幻觉）
2. **筛选层（可选但关键）**：先剔除"无知"样本（HellaSwag：4-way softmax P(correct)>0.3；TriviaQA：y_true rank≤50），只对"模型知道"的样本谈幻觉——无知与幻觉在信号上完全混淆，不筛则检测被拖累
3. **信号层**：幻觉样本与正确样本在内部状态/输出分布中存在线性可分的差异（truth direction / LR probe 能学到 0.75+ 的排序）
4. **评估层**：AUROC ≥ 0.85 是项目自设的"检测闭环达标线"，实际判定时在验证集上定阈值
